2. THE QUANTITY MEASURED, AND WHY THE OLD ONE WAS INSUFFICIENT
--------------------------------------------------------------------------------
    Monitor's real per-cycle order:

        O(i) foreground observation timestamp
          -> real Win32 foreground read
          -> real Browser / UIA address-bar read
          -> Resource Intent
          -> COSINE / MIRL / SINE / Blacklist / break admission / Study advance
          -> COSECANT.advance()            <-- A(i)
          -> COSECANT.observe_return(O(i))

    COSECANT has TWO continuity gates and advance() runs FIRST:

        advance()        while RETURN_CONFIRMING:  A(i) - O(i-1) > G -> stale
        observe_return():                          O(i) - O(i-1) > G -> restart

    Therefore the dominant quantity is

        E(i) = A(i) - O(i-1) = dO(i) + L(i)

    where dO(i) = O(i) - O(i-1) and L(i) = A(i) - O(i).

    The historical measure_cadence.py measured dO only, with a scripted
    foreground reader and scripted browser reads. It is preserved untouched as
    C0 evidence and contributed no sample to this dataset.

    IDENTITY VERIFICATION
        Every one of the 1600 rows was checked for E == dO + L.
        Violations: 0.  Worst delta: 1e-9 s (float rounding).


3. INSTRUMENTATION METHOD — NO PRODUCTION MUTATION
--------------------------------------------------------------------------------
    All recording is done by LAB-only delegating wrappers. No profiler code was
    inserted into monitor.py or cosecant.py, no call order was changed, and
    advance() is never called an extra time.

    RecordingForegroundReader   delegates to the REAL WindowsForegroundReader
                                and times the read
    make_recording_browser      wraps the REAL BrowserEvidenceAuthority.observe
                                and records STATUS ONLY
    make_recording_intent       wraps the REAL ResourceIntentAuthority.observe
                                and records the OPAQUE identity only
    RecordingCosecant           subclasses the REAL CosecantRuntime; overrides
                                _read_monotonic purely to OBSERVE the value
                                production already computes -- no second clock
                                read is introduced

    Everything downstream is the genuine production object: real Win32
    foreground sampling, real UIA address-bar reading, real Resource Intent,
    real Monitor coordinator, real Study/COSECANT/SINE/MIRL/COSINE/Trigger/
    Blacklist/storage, at the real DEFAULT_POLL_SECONDS = 1.5.

    PRIVACY
        No URL, window title or page content is recorded in any artifact.
        resource_stable_key is Resource Intent's own irreversible hash -- the
        same value production already persists as resource_key.

7. MEASUREMENT PROBE BIAS — RESOLVED BY CONDITION E
--------------------------------------------------------------------------------
    CosecantRuntime.advance() returns EARLY, before reading its monotonic
    clock, whenever no break is active. So in conditions A-D the exact internal
    value does not exist and the instrument recorded advance_call_ns, taken at
    wrapper entry before the lock and the state check. That is a LOWER BOUND on
    the value production uses, and it biases E downward -- toward looking safer
    than reality.

    Condition E is the only condition where a break is genuinely active, so it
    is the only condition that can measure that bias directly.

        advance source in E: internal = 319, call-entry = 1

        bias = advance_internal_ns - advance_call_ns   (seconds)
            n=319  min=0.0000  mean=0.0000  median=0.0000
                   p95=0.0000  p99=0.0000  max=0.0010

    RESULT: the call-entry approximation used in A-D was experimentally bounded
    in this run at approximately 1 millisecond worst case. Against a G decision
    measured in tenths of a second that is negligible, so the A-D datasets can
    be treated as measuring the intended quantity.

    WHY ONLY 319 OF 320 E ROWS HAVE advance_internal_ns
        The single exception is sequence 2, recorded with
        cosecant_state = INACTIVE. It is the first interval of the run, taken
        during the cycle in which the break was still being admitted, before
        COSECANT entered BREAK_ACTIVE. advance() therefore still took its early
        return and never reached its clock read. The row is retained in the CSV
        with advance_internal_ns blank and advance_source = advance_call_ns.
        It is not omitted, and it is not fabricated.

9. TAIL MECHANISMS — THREE DISTINCT SOURCES, PRESERVED SEPARATELY
--------------------------------------------------------------------------------
    The largest excursions do not share one cause. They are recorded here
    separately rather than merged into a single "jitter" number.

    (i) BROWSER / UIA LATENCY — conditions B and D
        B's two worst intervals were degraded reads, not successful ones:
            E 2.8283   dO 1.5031   L 1.3252   browser_status window_not_found
            E 2.6767   dO 1.5005   L 1.1762   browser_status address_value_invalid
        Within B, L median was 0.0824 s on 295 successful reads versus 0.0067 s
        on 25 cycles with no UIA read at all -- and the failure cases cost
        1.2-1.3 s. D's worst interval (E 2.6531, L 1.1542) carried a SUCCESSFUL
        ok read during an identity transition.

    (ii) SCHEDULER / OBSERVATION-GAP EXCURSION — condition E
        E's maximum has a different shape from B's and D's. It is the ONLY
        top-tail event in the dataset dominated by dO rather than L:
            E 2.5383   dO 2.4169   L 0.1214   browser_status ok
        This is the break-admission cycle (sequence 2, cosecant_state
        INACTIVE). The preceding cycle performed C5 admission work -- validate
        the target, pause Study, start the break, publish the BREAK context --
        which delayed the NEXT foreground observation. It is a one-off
        transient at break start, not steady-state break behaviour.

    (iii) STEADY-STATE ACTIVE BREAK — condition E, BREAK_ACTIVE only
        Excluding that admission transient, the 319 intervals where COSECANT
        was genuinely BREAK_ACTIVE were the tightest tail in the whole dataset:
            dO median 1.5007  p99 1.5132  max 1.5146
            E  median 1.5680  p95 1.6344  p99 1.6873  max 1.7144

        Stated as a measurement only, with no recommendation attached: G gates
        continuity while a break is running, and in that state the observed
        maximum E was 1.7144 s. Whether the admission transient and the UIA
        failure excursions must also be absorbed by a static G is exactly the
        architectural question C9-B has to answer, and this report does not
        answer it.


10. STABLE vs TRANSITION — EXPLORATORY ONLY, NOT AUTHORITATIVE
--------------------------------------------------------------------------------
    STATUS: INSUFFICIENT TRANSITION SAMPLE. NO CAUSAL CLAIM IS MADE.

    D_switching
        STABLE      n=313  non-ok 6.1%   L median 0.0642  E max 1.9441
        TRANSITION  n=6    non-ok 0.0%   L median 0.0870  E max 2.6531
    E_cosecant_break
        STABLE      n=307  non-ok 2.9%   L median 0.0691  E max 1.7012
        TRANSITION  n=12   non-ok 25.0%  L median 0.0606  E max 1.7144

    WHY THE TRANSITION GROUP IS NOT TRUSTWORTHY
        The instrument detected only 6 identity changes across D's 320
        intervals -- one every 80 s -- against an intended switching rate of
        10-30 s. Two independent facts explain this and both were verified
        against the raw data rather than assumed:

        1. UNDER-DETECTION. resource_stable_key is derived partly from the
           normalised window title. Two tabs on the same site can produce the
           SAME identity, so genuine tab switches collapse into "STABLE". D
           recorded only 5 distinct stable_keys and 2 distinct hwnds in 320
           intervals.
        2. UNDER-SWITCHING. The observed dwell pattern was
           [20, 6, 29, 5, 28, 80, 152] cycles. The final two identities held
           for 120 s and 228 s. Roughly the last four minutes contained no
           detected change at all. No title-collision artefact explains a
           228-second unbroken stretch.

        Consequently the TRANSITION rows are a FLOOR, not a measurement, and
        some STABLE rows are probably mislabelled transitions.

    WHAT MAY BE SAID
        D's single worst interval was a transition carrying a SUCCESSFUL ok
        read with L = 1.1542 s. That is a genuine observation and it is
        preserved. It is consistent with the hypothesis that a moving sensory
        target can make even a successful UIA read slow.

    WHAT MAY NOT BE SAID
        "Transitions cause the tail." n=6 cannot support that, and this report
        does not assert it. If the eventual G decision turns on whether the
        2.6-2.8 s events are transition-specific, a dedicated supplemental
        experiment (different domains, separate windows, sustained deliberate
        cross-site switching) would be required first.

14. INSTRUMENT DEFECTS FOUND AND FIXED DURING C9-A
--------------------------------------------------------------------------------
    Both were SILENT failure modes that would have produced plausible-looking
    numbers. Both are LAB-only fixes; production diff remained zero.

    (a) NO SINGLE-INSTANCE PROTECTION
        Cause of Exclusion 2. measure_c9_runtime_gap.py now takes an exclusive
        lock (c9_artifacts/measurement.lock) recording pid, condition and UTC
        start time, refuses to start if it exists, and releases in a finally
        block. A measurement that cannot prove it ran alone is not
        authoritative.

    (b) CSV SCHEMA DRIFT
        Adding resource_stable_key and hwnd made the instrument write 20-field
        rows while the existing file still had an 18-field header. Appending
        does not crash -- it silently misaligns every later column, so values
        read back against the wrong names and look valid. Five smoke rows hit
        this. The CSV was migrated to the unified 20-field schema and
        append_csv now REFUSES to append under a mismatched header.

    BACKFILL POLICY
        Conditions A, B and C were collected before resource_stable_key and
        hwnd existed. Their rows carry those two columns BLANK. They were not
        back-computed, estimated or fabricated, and their summaries correctly
        print "STABLE vs TRANSITION: NOT DERIVABLE -- this run predates the
        opaque resource_stable_key column."
